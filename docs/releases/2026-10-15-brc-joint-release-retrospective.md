## 基于事实的判断：缺陷、流程遗漏与正常等待

**安全门槛总体发挥了作用，但发布工具流程完整性、状态识别与并发场景覆盖不足。**
被安全阻断本身不是事故；产生阻断的原因仍需分类，不能用“门槛正常”掩盖代码缺陷。

| 类型 | 本次问题或等待 | 处理性质 |
| --- | --- | --- |
| **代码缺陷** | 暂停 Policy、已失败 Generation 与未解除恢复围栏组合无法被合法迁移路径证明静止 | 增加严格暂停静止性证明；仍保留负围栏和原授权，缺证据继续拒绝 |

## 六条长期经验

### 1. 完整识别所有数据库写入者

**Writer Inventory 必须明确且可复用。** 本次包括 Observation、Entry、Lifecycle、
Reconciliation 和独立 Owner API；以后仍需按实际机器配置核验，不能假定数量永远固定。
停止动作与停止结果必须覆盖同一组写入者，不能依靠执行者记忆。

### 2. 暂停交易是合法状态

**不得为了部署要求 Owner 恢复交易权限。** 只有旧任务已真实终结、无交易负债、
源静止性及原授权／围栏证据完整时，才能使用已实现的严格暂停迁移证明。
暂停不会自动意味着任意恢复路径可以完成；ENTRY 和 Selection 控制独立，但实际激活／恢复仍有共同门槛。

### 3. 停写证明与启动后验收分开

**停写阶段**验证源事实、历史、控制身份与保留摘要；**启动后**允许正常运行产生新事实，
同时检查精确身份、Owner 控制、当前成员和安全边界。
不得重写基线来接受漂移，也不得要求正常运行后的计数永远冻结。

### 4. 认证输出有界，计算保持完整

**完整校验必须在源端完成。** 远程传输采用结果、总摘要、表级摘要、计数和必要失败明细；
展示裁剪不能改变 PASS／FAIL、跳过计算或削弱认证。

### 5. 完整复核路径后冻结候选

公共发布逻辑变更同时检查 **R3 常规发布和 R4 兼容升级**的受影响路径、失败恢复与重启顺序。
先做必要定向回归，冻结准确 SHA 后只运行该发布类别所需正式认证；同 SHA 等待外部条件时复用认证，
不同提交或类别不能继承旧 manifest。不因本复盘扩大日常测试组合。

### 6. 四类完成结果分别举证

| 结果 | 必要证据 | 不能作为替代的现象 |
| --- | --- | --- |
| **Software** | 代码／Schema／Seed 身份、保留检查、部署及健康检查通过 | 文件上传完成、进程启动 |
| **Entry** | 当前 Owner Resume 证明、fresh facts、正式 promotion | 软件上线、聊天中已有部署许可 |
| **Authority** | 当前 Universe／Generation／Selection／Authority 和原授权一致有效；双向策略核对双边 | Snapshot 成功、Pending 意图、服务活跃 |
| **Natural Lifecycle** | 真实 Ticket 的保护、退出、对账、Settlement、Review 与资源释放 | 下游 fixture、观察价格、人为制造订单 |

## 轻量改进优先级

**如果只选两项，优先完整 Writer Inventory 和发布前只读预检。** 以下为经验性待办，
不代表新增工程已实施，不扩大当前发布或研究主线。

| 项目 | 最小改进方式 | 状态与优先级 |
| --- | --- | --- |
| **完整 Writer Inventory** | 在现有发布入口统一列出写入者、状态和停止结果，停止动作与检查使用同一清单 | 下次发布前优先补齐；已有 API 停写检查，不等于已统一流程 |
| **发布前只读预检** | 复用正式验证逻辑，提前显示 Ticket、Generation、Vacuum、未决任务、围栏和真实等待条件 | 下次发布前优先补齐；行动时仍须重新核验 |
| R3／R4 共用路径回归 | 公共逻辑改动时复用关键模拟回归，覆盖对应启动／恢复交错 | 已有本次回归，按实际缺口小幅补强 |
| 暂停静止性证明 | 保留终态、排空、Owner Pause、零负债的严格证明 | 本次已实现，不另立项目 |
| 分阶段 Postflight | Selection 启动前验保留，启动后验当前身份与安全边界 | 本次已实现，不另立项目 |
| 有界摘要 | 源端完整计算，传输摘要与诊断 | 本次已实现，不另立项目 |
| 分层验收口径 | 沿用 Software／Entry／Authority／Natural Lifecycle | 复盘沟通口径，不新建状态数据库 |

## 未来 R3／R4 发布的最小参考流程

1. **只读预检：** 核对候选、类别、完整写入者、当前交易负债与遗留任务；明确哪些是工程缺陷、哪些需合法等待。
2. **冻结候选：** 必要定向回归通过，R3／R4 受影响公共路径复核完成，再冻结准确提交。
3. **正式认证：** 按最重边界运行精确 R3 或 R4；仅涉及 API／Console 时运行对应认证，不对无关范围强加认证。
4. **停写切换：** 全部写入者停止、ENTRY 围栏有效；重新验证真实 flat／quiescent 和源保留，不复用预检时的动态事实。
5. **启动验收：** 验证身份、Schema、Seed、控制、Universe 和服务；遵循现有先验保留、后恢复 Selection 的顺序。
6. **独立启用：** 根据当前 Owner 决定和正式认证分别处理 ENTRY、策略及 Dynamic；部署不隐含启用。
7. **运行证据：** 核验真实 Authority；自然 Ticket 闭环等待市场与系统证据，不强制交易。

### 汇报状态的含义

| 报告状态 | 含义 | 本次例子 |
| --- | --- | --- |
| **BLOCKED** | 当前安全／身份门槛未满足 | Writer 未停止、源任务未静止 |
| **FAILED** | 执行或代码出现错误 | 输出传输问题、错误的启动／验收顺序 |
| **WAITING** | 正式路径中合法等待外部条件 | 真实 deadline、Owner TOTP、时间窗、暖机槽 |
| **PASSED** | 该阶段全部证据通过 | 软件完成与真实 Authority 接管分别 PASS |

这些是报告解释，不新增或替换发布工具现有 `running / waiting_external / retryable / blocked / completed`
状态枚举；同一次尝试可以安全 BLOCKED，同时其根因属于需要修复的工程缺陷。

## 不扩大工程范围

- 不缩减认证或放松静止性门槛，不为了发布自动恢复 ENTRY 或强制结束交易。
- 不建立复杂发布编排平台、独立审批、第二状态数据库或全面重写 Deployment。
- 不把正常等待都转化为并发调度改造，不为证明稳定制造实盘 Ticket。
- 现有修复与回归保留；未来修改只针对确有证据的缺陷，测试与改动成比例。

**当前主线仍是自然交易闭环、对账稳定性和 ALPHA-02。** 本复盘只为未来发布提供少量可复用检查，
不将发布工程扩张为新的长期项目。

## 最终经验

**可靠发布应在危险操作前准确阻断，在合法条件满足后继续推进，并清楚说明每个阶段完成了什么。**
这次应吸收的是减少临时分析和反复修补的流程经验，同时保留已经发挥作用的安全门槛。
