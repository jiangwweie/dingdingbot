# 首尔小时 SOR 拆组：关键负面测试案例

**状态：测试设计，待实现与执行。** 对应[多空独立策略设计](2026-11-21-seoul-sor-directional-strategies.md)。目标是发现会造成错向开仓、均线绕过、重复开仓、预算扩大或历史归属错误的实现。表内 ID 是规格编号。

## 1. 测试基线与读数

- **数据**：用冻结时钟、首尔产品测试账户、两个独立策略组、真实迁移后的本地 `brc-manual-pg` 和记录调用的 venue fake。基准场景的策略开关、容量、行情新鲜度、合约规则、持仓模式均合法；每个负例只改变该行条件。使用仓库 `.venv` 及 `scripts/local/manual_pytest.sh`。
- **时间与行情**：固定 `T` 为 UTC 4h 闭合边界，如 12:00。50 根有效 BTC 收盘默认均为 `100`；正对照取前 49 根 `100`、末根 `101`（SMA 为 `100.02`），负对照末根 `99`（SMA 为 `99.98`）。币种小时突破与 BTC 价格夹具独立。以原始 Decimal 而非屏幕显示的舍入值比较。
- **双向正对照**：同一正常交易日，用不同品种分别制造合法向上、向下穿越。各自策略单独开启时应能走到本地 fake 的 ENTRY 接受、Initial Stop 确认。这样能识别因全局暂停或夹具失效而“全部零发送”的假通过。
- **观察点**：准入前的拒绝检查该信号的首阻塞原因及零新增 Claim／Ticket／ENTRY；已有 Claim 或 Command 的最终发送拒绝检查 venue ENTRY 调用为零、无新一代 ENTRY，并按既有机制收尾。在有其他交易的场景以具体 signal／ticket／command ID 限定计数。冻结链路的保护动作与新开仓分别计数。

## 2. 核心用例

### 2.1 策略控制与身份

| 编号／层级 | Given／When | Then：通过条件 |
|---|---|---|
| **S01 · PG＋HTTP＋全链** | 两组开启。用普通策略 API 只暂停多头，触发一多一空。交换两个方向再测一次。 | 暂停侧无新 ENTRY，对侧符合条件时恰有一笔 ENTRY。状态读回、重启后读回与实际发单一致；策略组间的控制版本互不覆盖。 |
| **S02 · PG＋HTTP** | 全局 ENTRY 已暂停，再由 Owner 恢复新多头；另用无授权请求操作新空头。 | 多头仍受全局暂停，不能开仓；无授权请求失败且空头控制版本不变。普通 Owner 恢复流程的权限与审计不退化。 |
| **S03 · 域＋PG** | 把空事件配给多组、把旧组同名短事件配给新组、把新组的旧绑定摘要换成另一方向。分别触发准入。 | Registry／Scope／绑定核对在对应层失败；无错误方向的 Claim、Ticket、ENTRY。旧 `SOR-1H-001`、退役 `SOR-001` 即使直接调用 resume 接口也不能获得新 ENTRY 权限。 |
| **S04 · 全链** | 已有新多头 AUTO 票，暂停多头并让 BTC 穿到均线下，再产生 TP1 成交；配对夹具使用已外部接管的 MANUAL 票。 | AUTO 按冻结方案维护剩余数量的保护，暂停不得主动平掉该票。MANUAL 不自动换止损、撤单或退出；两者均不得被当成一次新的开仓。 |

### 2.2 MA50 与发送边界

| 编号／层级 | Given／When | Then：通过条件 |
|---|---|---|
| **M01 · 域＋准入** | 已启用 MA50，存在合法多头突破，参数化末根收盘低于、等于、高于 SMA；另设收盘与 SMA 显示舍入相等但原值不同。 | 等于、低于均以 `ma50_not_bullish` 拒绝；严格高于且其他门槛通过时获准；判断与原始 Decimal 值一致。 |
| **M02 · 行情＋PG** | 已启用 MA50，输入 49 根、50 根中重复或断档、混入未闭合 bar、末端与 UTC 边界不齐、缺少快照。旧快照保留但已过期；分别在到期前一毫秒和到期时尝试。 | 畸形输入不能产生新有效快照；缺失／过期按对应原因阻止多头。`now == valid_until` 时不能用上一窗口放行，未闭合行情不能把阴性改成阳性。 |
| **M03 · 配置＋PG** | 多头未列入有效配置、绑定与 Profile 哈希不符，或向空头提交开启均线开关。另以真实 Owner 控制流程分别关闭、重新开启多头过滤。 | 缺配置和错绑定拦截多头，空头开关请求拒绝。多头可授权关闭并跳过均线检查，重新开启后恢复检查。配置修订和其他事件参数可核对。 |
| **M04 · PG＋全链** | 第一次以有效偏多快照形成 Claim，发票前跨 4h 边界；另一次在合法发票后、最终发送前令新快照低于均线、过期或绑定漂移。 | 第一种场景无新 Ticket；第二种保留原始 Ticket／Command 审计、venue 零 ENTRY 发送。不得复用旧证明、续签旧命令或新增 ENTRY；预算按既有收尾流程释放。 |
| **M05 · 全链对照** | BTC 低于均线或专用 MA50 快照缺失，空头突破，其自身行情、退出绑定和其他门槛全部健康。另造不满足下穿条件的空侧反例。 | 合法空头可发一笔 ENTRY，不出现多头 MA50 拒绝；未下穿则无空头信号与新单。多头开启过滤时按 M01/M02 拦截。 |

### 2.3 选币、首次触发与共享预算

| 编号／层级 | Given／When | Then：通过条件 |
|---|---|---|
| **U01 · PG 选币** | 相同日期和原始输入生成两方向权限，覆盖 Static 与 Dynamic；暂停／恢复一侧并重启。尝试将其 Authority 或旧组 Snapshot 用在另一侧。 | 相同条件下各侧输出与原同侧成员一致；组、Event、有效期和身份摘要精确匹配。错配拒绝，对侧活动指针、首触发状态和权限无误写。 |
| **U02 · 域＋PG** | 同日同币首次向上突破在 MA50 下被拒，随后均线翻上而币价仍在区间上方；交替重放同一闭合 bar、重启或恢复。 | 原突破只消费一次，不能凭均线翻转或恢复补开；空方向的首次下穿仍可独立消费。下一合法会话的新突破可正常触发。 |
| **U03 · 迁移＋全链** | 旧小时组在当日已消费一次多向突破，空仓切换到新 ID；另设暂停期已出现突破以及缺少部分会话 bar 的样本。 | 新多组在同一日不重复消费旧／缺口内事件。证据不全时不准入，恢复按既有审计；不得无证据手动置为已武装状态。 |
| **R01 · PG 容量** | 用不同币占满原 `opening_range` 家族额度，保持账户总额度尚有剩余，再用拆分后另一组请求准入；另分别只耗尽账户／同向额度。 | 原家族总额仍跨组计数，分别触发对应容量限制；没有因出现第二个组 ID 获得额外名额、风险或保证金。额度真实释放后可按既有规则重新评估新信号。 |
| **R02 · PG＋全链** | 同一账户／品种已有反向仓位、非终态票或零仓带残单，另一个新组恰出现合格突破；对已有同向票也重复触发。 | 拒绝反向占用或重复／加仓。健康校验和既有持仓保护持续工作；同一 Episode 不出现第二张票，同票不出现第二代 ENTRY。 |

### 2.4 切换、历史与界面

| 编号／层级 | Given／When | Then：通过条件 |
|---|---|---|
| **H01 · 迁移演练** | 准备带旧小时多空终态票、有效 Review 修订及真实形状的退出配置。原组曾启用或已暂停各测一次。先尝试带非终态票切换，再在正式空仓停写条件下演练；模拟提交前中断及重跑。 | 非终态源按既有切换门禁拒绝。成功后两个新组初始暂停，旧组不能新开；不存在旧新同时可发单的状态。重跑无重复身份、重复授权或交易命令；失败保持受限并可前向恢复。 |
| **H02 · PG＋API＋UI** | 同一标的旧多、旧空、新多、新空各有交易，且含一笔净额缺失／Review 有修订。打开旧详情链接，分别按组和方向筛选，再汇总同一窗口。 | 旧 Ticket、Review、原绑定键及历史保留摘要一致；每票只计一次，读取有效修订；净额未知显式展示。新交易按新组归属，历史链接可读；旧组不显示可用的开启按钮。 |
| **H03 · 配置＋回放** | 旧多、空生效参数设置为与种子默认值不同。切换并保存其他策略的合法配置，加载两个新组的查看／编辑入口，做同输入 Live／Replay 对照。 | 两侧分别继承旧同方向的 TP1 比例与目标、时间／结构退出、Runner 及执行取整规则；其他事件参数不丢失。新多默认启用 MA50，授权保存后按实际选择读回。除批准差异外，信号、退出路径及容量结果与原同侧一致。 |

## 3. 如何使用这份规格

1. **先写失败用例**：优先落 S01、M03、M04、U03、R01、H01。失败证据须能区分误放行、误拦截、错误写入对象和历史被改写；每个负例同时跑对应正对照。
2. **复用测试入口**：单测从[小时检测器](../../../tests/trading_kernel/unit/detectors/test_sor_1h.py)与[退出配置](../../../tests/trading_kernel/unit/test_exit_configuration.py)扩展；PG 测试参考[控制面](../../../tests/trading_kernel/integration/test_owner_control_plane.py)、[会话选币](../../../tests/trading_kernel/integration/test_orb_session_selection_repository.py)、[前向保留](../../../tests/trading_kernel/integration/test_orb_forward_preservation.py)与[首尔退出配置](../../../tests/trading_kernel/integration/test_manual_exit_configuration.py)。保留现有发送拒绝、未知结果对账和权限测试，不为普通暂停另建交互流程。
3. **发布证据**：使用同一候选提交完成对应的迁移、全链、API 和前端认证，并验证首尔身份、历史保留与启用后控制读回。自然交易和实际 MA50 拦截按发生时记录，线上不造票验收。
