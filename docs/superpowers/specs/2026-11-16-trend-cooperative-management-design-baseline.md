## 1. 目标与适用范围

**有限风险地等待趋势，在趋势形成后保留大赢家；系统独立运行，Owner偶尔通过明确指令收紧风险。** 不要求稳定收益、每笔保本、高胜率或高频响应；也不因无法预先证明一定赚钱而拒绝作出设计选择。

本阶段只适用于首尔独立人工协作产品，不改变Tokyo。沿用既有Kernel、账户隔离和唯一执行链，不能为了新退出模式创建第二套订单管理器。

来源：本线程Owner明确意见；[实验目标](../../current/RUNTIME_ORDER_CAPABLE_EXPERIMENT_PROFILE.md)、[评估口径](../../current/STRATEGY_EXPERIMENT_EVALUATION_CONTRACT.md)。

## 2. 已确认的Owner决定

下表记录Owner原意。**已确认的是业务取舍，不等于具体算法、API或状态字段已确认。**

| 编号 | 已确认选择 | 设计含义 |
|---|---|---|
| D01 | 目标是趋势行情，接受其稀缺性 | 兼顾趋势期收益与非趋势期试错损耗，不追求持续交易 |
| D02 | 系统独立运行，偶尔收紧保护、减仓或暂停 | Owner不负责持续盯盘、每天判断方向或逐笔批准正常退出 |
| D03 | 结构退出为主，接受较大浮盈回吐 | 不默认叠加固定回吐比例、盈利后强制保本或固定金额锁利 |
| D04 | 认可方向选择、失败早退、不确定时降低风险 | 三项都应落实成系统规则，不能留给Owner临盘补全 |
| D05 | 同一区间连续失败，局部暂停，结构重新形成后自动恢复 | 限制该币种/方向的新尝试；不强平已有仓，不越过Owner手动暂停 |
| D06 | 按策略处理逆大盘机会 | 趋势延续型严格顺势；反转型可降低风险参与。精确策略分类待定义 |
| D07 | 首版不加仓，不提高账户或单票风险上限 | 正常风险最多回到原批准额度，不因盈利、保本或趋势标签扩大额度 |
| D08 | 系统不是高频量化，人工操作无很高时效性要求 | 闭合K线决策、低频轮询、每票串行调整；交易所已有止损仍实时保护 |
| D09 | 系统覆盖必要持仓操作，减少币安App与系统双线管理 | 系统内操作有明确意图、命令与续管语义；外部操作处理保留为应急边界 |
| D10 | 比较整个账户收益率与同期市场涨跌幅 | 明确同窗、资金流和市场基准，不将保证金收益率冒充账户收益率 |
| D11 | 手机主屏幕Web App，以必要写操作为主，后续可封装App | 最新选择取代原生iOS首发偏好；行情阅读、统计分析、复盘页面非必需 |
| D12 | 先沉淀交易方案，再沟通App，不急于开工 | 交易机制仍先设计；后续已授权手机静态原型，决定详见手机操作端设计 |

## 3. 完整业务链

**辨别机会 → 按行情与策略分配风险 → 失败早退 → 限制同结构重复试错 → 趋势确认后持续持有 → 人工可收紧或减仓而不丢失自动管理。**

### 3.1 行情与方向只约束适用的新准入

区分方向明确、方向不清/区间震荡、结构转坏等状态，并根据策略类别决定准入或降风险。状态定义、周期、切换缓冲与缺失数据处理尚未冻结。

大盘状态不能直接替代单币结构或策略信号。趋势延续型与反转型的边界由明确版本规则决定，不能凭策略名称或最近盈利强行分类。

市场标签变化不自动平掉所有旧仓、反手或取消保护。既有交易按冻结计划及自身失效条件退出；后续新交易使用当时有效准入规则。

### 3.2 非趋势阶段控制试错成本

- 一次失败退出后，信号重新出现不当然意味着结构已经更新。
- 同一段市场结构内记录尝试、失败与消耗，达到规则条件则局部暂停新准入。
- 只有预先定义的新结构条件成立才自动解除系统自己的暂停；Owner暂停、事故/证据门禁分别保留。
- 不确定时降低金额风险，不能靠无限收紧止损假装减少风险；最小量、精度、费用和最低有效规模不满足则明确不入场。
- 相关币种的共同方向风险要计入已有总预算；是否新增跨币种试错额度、如何分组是待设计事项，不能宣称已实现。

这不是已批准新增全账户每日亏损熔断，也不是所有策略共用一个固定冷却计时器。它限制未来新尝试，已有AUTO仓保护与退出持续运行。

### 3.3 失败早退与趋势持有分阶段

交易未发展时，使用策略自身的结构失效、突破收回或时间条件退出；判断已错不必等到初始Stop。时间规则要反映“迟迟不发展”，不能与Runner周期意外绑定。

趋势形成后，主要仓位采用结构追踪，不因小浮盈自动兑现或把Stop搬到盈亏零点。正常回撤与趋势失效分开。初始Stop、已确认Stop与Owner收紧约束不可被后续计划放松。

**方案A是主研究方向：无固定TP的完整Runner、真实成交与趋势里程碑解耦。** 不是已经批准所有策略统一取消TP。分策略进入条件、失败条件、持仓期限、结构/ATR参数与成本退出仍需形成可评审规格。

## 4. 方案选择与已有回放的正确位置

| 方案 | 定位 | 不应推导的结论 |
|---|---|---|
| A：完整趋势仓＋结构退出 | 与右尾愿景最贴合的主方向，优先细化SOR | 已证明所有策略或所有市场最优 |

## 5. 人工协作与系统执行权

### 5.1 已明确的核心意图

**Owner通过系统表达风险意图，Kernel执行并继续管理；系统内人工指令不自动等同整票MANUAL。** 这是未来目标，现有规则尚未改变。

核心能力是收紧保护继续AUTO、减仓继续AUTO、暂停新开仓。减仓按真实成交重算余量、保护及相关退出订单，禁止补回Owner减掉的仓位。

### 5.2 候选操作范围

| 操作 | 当前讨论地位 | 后续需明确 |
|---|---|---|
| 收紧止损/保护底线 | 核心协作目标 | 价格或金额输入、精度、成本展示和确认规则 |
| 按数量/比例减仓 | 核心协作目标 | 执行方式、部分成交、剩余最小量、期限 |
| 暂停新开仓 | 已确认常用控制 | 全局/策略范围、恢复授权及与系统局部暂停的关系 |
| 系统受控结束单笔 | 已提出的合理候选，待App操作范围讨论 | 确认、在途订单和残单收尾 |
| 指定价格部分止盈及修改/取消 | 补齐日常操作的候选，尚未逐项冻结 | 与结构Stop、同票多个退出计划的数量约束 |
| 完全人工接管 | 保留独立语义，入口细节待定 | 真实授权和当时未决命令处理 |

不因币安提供某项功能就默认纳入：加仓、放宽止损、反手、提现、转账、凭据变更均不属于本次已确认范围。

### 5.3 外部App边界

未来日常操作尽量由本系统完成，币安App作为应急工具。外部有效干预继续需要归属核实；未明确修订前，沿用永久MANUAL及未知进入REVIEW_REQUIRED。不得从仓位减少猜测“Owner希望自动续管”，不得让既有MANUAL悄然回AUTO。

来源：[现行Owner运行模型](../../current/OWNER_RUNTIME_OPERATING_MODEL.md)、[原接管决定](2026-11-06-app-manual-takeover-v1-owner-decisions.md)。

## 6. 低频、串行、可恢复的执行原则

人工减仓无需毫秒响应。建议每票一次调整：登记意图与授权 → 暂停该票新Runner调整 → 保留已有保护执行减仓 → 核实真实成交和余量 → 更新保护/退出计划 → 确认后恢复正常自动管理。其他票不因单票操作被无谓阻塞。

**暂停新的改单不等于暂停交易所Stop。** 等待期间已有Stop可能触发，必须核对最终仓位与订单。不能依靠“系统不是高频”忽略交易所并发事实。

- 所有交易所写入来自现有durable Command；网络I/O在数据库事务外。
- 同票请求幂等，版本/数量过时重新核实；未知结果不盲重发。
- 保留有效保护，避免先撤掉唯一Stop再等待减仓完成。
- 部分成交、Stop与减仓交错、断线、重启、手动应急介入都有明确核实/终止路径。
- 减仓后超量退出订单的语义须按实际Hedge Mode协议验证，不能假设设置一个参数就一定防止反向或超量处置。
- 客户端可以离开，处理进度保存在服务端；结果查询和通知是显示渠道，不创造执行权。

这是设计原则，尚非逐步可执行的交易所协议规格。

不得让无TP方案通过填零数量或伪造TP完成绕过旧合同。应使用明确的新退出计划语义；已有有TP模式继续如实记真实部分/完整成交。旧票不临盘换计划，旧历史不改写。

## 8. 收益评价与风险边界

账户收益与同期市场涨跌幅的比较必须明确时间、基准和资金流。5倍杠杆不等于整段账户5倍敞口；参与时间、名义敞口/权益、减仓、试错与费用共同决定结果。

本阶段先改善捕获和选择效率，不将“账户收益至少是市场跌幅两倍”设成加杠杆或提高风险的授权。关注净R、账户回撤、利润回吐、趋势贡献、非趋势期损耗、资金占用与新机会排挤。

单票初始风险有界不保证累计亏损有界，也不保证跳空/费用后的实亏绝不超出计划。局部试错规则与已有总体风险约束需要共同作用，不追加未经确认的全局熔断。

## 9. 待设计项：不把示例当成决定

1. **行情分类**：具体数据、周期、切换缓冲、未知状态；大盘与单币冲突的优先级。
2. **策略分类**：哪些事件算趋势延续或反转，SOR不同阶段如何处理，不能仅依名称分类。
3. **局部结构与重试**：结构身份、失败定义、次数/消耗、跨策略范围、新结构重置；是否需要跨币种共享消耗规则。
4. **缩减风险**：各状态风险水平及最小规模处理；不能把缩减后的额度误当成不足原额度而全部拒绝，亦不能向上补回。
5. **退出阶段**：确认里程碑、结构窗口、ATR、超时与成本退出、无TP与真实TP模式的数据结构。
6. **Owner操作协议**：执行价格方式、期限、部分成交、过期预览、命令排序与外部应急干预。
7. **收益基准与数据**：账户收益的资金流调整、市场基准、可实现组合再准入与事实缺口。

上述由工程方提出有理由的初始规格，展示取舍再讨论；无需Owner凭感觉填写技术参数。若需提高风险、加仓、放宽Stop、强制平旧仓或新增全账户暂停，必须作为新的业务决定明确提出。

## 12. 验证与后续授权边界

先完成业务规格再决定实施。未来验证应覆盖闭合行情与无未来数据、状态来回切换、局部暂停/恢复不越权、无TP生命周期、精确部分成交/未知命令、重启恢复、结构周期与持仓时限解耦、费用与数量守恒、Owner指令并发及外部接管。

回放应包含趋势与区间、同币/相关币重复试错及组合资金/容量约束；验证用于显露错误和代价，不要求事先证明稳定收益。测试与研究不是生产授权。

若后续需要持久化升级，遵循正式停新入场、flat、停writer、前向迁移、历史保全和精确认证；不得在活动票上暗改冻结规则，不以降级丢弃已经确认的保护约束。

**交易工程仍处于设计阶段；后续Owner已授权手机操作方案文档与静态原型。没有生产功能开发、部署、参数激活或服务器操作。**
