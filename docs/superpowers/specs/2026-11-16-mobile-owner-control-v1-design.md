## 1. 产品定位与当前决定

首版是**手机优先的主屏幕Web App**，后续可封装App。不是沿用旧Web缩屏，不做原生iOS首发，不需要为原型购买Apple开发者计划。

采用币安式深色、紧凑信息、黄按钮、多空颜色与底部面板操作习惯；保留BRC身份，不使用币安品牌标识，不让用户误以为在交易所App内。

**以必要写操作为主**；只读取选择对象、确认操作及了解结果所需的持仓/委托/管理状态。不要求行情图表、分析、收益排行或复盘。

来源：本线程Owner逐项同意，包括策略启停、默认市价、去除TOTP、单可信设备、关键通知、主屏幕Web、单个人工止盈及保护优先关系。交易方向见[业务基线](2026-11-16-trend-cooperative-management-design-baseline.md)。

## 2.1 补充决定已确认（2026-11-16）

人工TP使用普通GTC限价，触价不保证全部成交；减仓使原TP量超过余仓时先改/取消TP，不自动联动。对保留自动TP的票，人工计划替换原获利退出计划，目标完整真实成交后沿原BE/Runner继续；取消人工计划保留保护与失败退出，不恢复旧TP。详见详细设计Q1/Q2。

## 3. 页面与操作流程

### 设计准则：行为表达意图

**不以说明文字堆砌产品意图。** 用不可取消的保护操作、单一TP编辑入口、启停开关的联动状态、确认页数量差异、处理中锁定及结果回写表达规则。普通页面删去重复解释；复杂原因按需查看，确认和异常文案保持短而具体。原型评审说明放在桌面演示区域或模拟控制面板，不污染正式手机信息流。

### 3.1 持仓

展示币种、方向、策略、AUTO/处理中/待核实/MANUAL、实际余量、入场/当前价格、浮盈亏、已确认保护价及数据时点。财务展示为必要操作上下文，不增加收益分析模块。

可直接减仓、设置止盈止损、全平。比例快捷键25%/50%/75%，自定义数量。超过余量、低于可执行量、输入不合法明确阻止；不静默加大减仓。

### 3.2 当前委托

系统保护与人工止盈分开标识。系统止损只能调整，不能直接取消；人工止盈可改/取消。处理中请求可查看状态，不提供可能造成重发的重复提交按钮。

必要保护、在途减仓和人工止盈同时存在时，仍由Kernel处理数量与次序，客户端不自主调用交易所。原型只模拟最终一致更新，不证明真实竞态已实现。

### 3.3 主控

全局和策略开关控制新开仓，明确写出已有仓位继续管理。Owner启用选择与“当前实际可开仓”分开；全局暂停、局部结构暂停和风险门禁可能阻止已启用策略。

系统自动恢复仅解除自身局部暂停，不能替Owner恢复手动暂停。退休策略不因本页面出现而复活。

### 3.4 确认、处理中、结果

编辑 → 预览 → 确认 → 已受理/处理中 → 已完成、明确失败或结果待核实。不能把请求受理当成实际完成。

确认显示对象、动作、数量/价格、估算余仓、是否继续自动管理；市价成交价不保证等于预览价。预览后仓位或版本变化需重新核对，不能照旧执行。

未知结果只允许查询进度；明确拒绝后可以重新编辑并形成新请求。只有确认已完成才显示新保护/余量。网络断开不能让旧数据继续写入，已有交易所保护不依赖手机在线。

## 4. 保护与委托优先关系

| 事件 | 处理 |
|---|---|
| 系统Stop比Owner约束更松 | 保留更严格的已确认保护 |
| 系统Stop比Owner约束更紧 | 可以继续收紧 |
| 人工部分TP成交 | 记录成交，按余量维护保护，保持AUTO |
| 结构Stop先成交 | 核实退出并清理已不需要的TP |
| Owner取消人工TP | 仅取消该计划，不取消结构Stop |
| Owner减仓后旧TP数量不再适用 | 暂停冲突调整并重新核实；需要改计划时明确呈现，不静默扩大退出量 |
| 已MANUAL或归属不明 | 不通过新页面暗中恢复AUTO，沿现有核实/接管规则 |

“最多一个人工TP”不等同于宣称所有当前策略已取消自身TP。新模式与旧有TP票的共存/替换数量规则是后端规格待定项，原型默认展示未来无固定TP模式，不连接旧生产票。

## 5. 认证与安装边界

长期会话需要可续期、可撤销的服务端凭据与设备绑定。去除TOTP是目标认证合同变更；当前生产规则在实施前仍生效。独立管理渠道、首次绑定码签发/有效期、恢复身份、丢失设备撤销、并发会话处理仍需安全设计。

Web不能仅凭设备名称证明唯一硬件，也不能承诺浏览器永不清理会话。Face ID仅为可选交互方向，WebAuthn/通行密钥与设备凭据取舍尚未冻结；原型不得假装已完成真实可信设备认证。

主屏幕添加、全屏显示、系统推送取决于iOS/Web支持和用户权限；未安装或不支持时提供明确状态，不能强制通知作为开仓门禁。原型只展示入口，不宣称已完成真实PWA安装与推送。

## 6. 首版不做

手动新开仓、加仓、反手、放宽止损、资金转移、交易所密钥管理；行情/分析/复盘；多档人工TP；聊天机器人直接发单；毫秒级追价。

不将App原型当成后台已具备受控减仓、无TPRunner或新授权机制的证明。

## 7. 静态原型约定

入口：[手机交互原型](../../prototypes/mobile-owner-control-v1/index.html)。单文件、模拟仓位、无API/外部资源/真实认证；刷新重置。全部“成功、失败、待核实”均为演示情景。

可体验持仓/委托/主控、减仓/全平/保护/单TP设置和替换/取消、策略和全局开关、确认与后台处理感受。桌面附原型控制面板，可切换成功/拒绝/待核实、断网及重置；手机中通过顶部原型标记打开。

自定义图标和布局接近熟悉的交易操作风格，无币安品牌资产。无生产代码修改、无上线授权。点击原型交易按钮只改变本地模拟状态。

## 8. 待设计而非已批准实现细节

- 真实订单协议、最小量与价格精度、改单能力、部分成交和在途取消的核实路径。
- 比例基于预览仓位还是提交最新仓位的冻结规则、有效期与重确认门槛。
- 人工TP已确定为普通GTC限价；精确交易所价格校验与成交/取消协议仍需验证。
- 可信设备授权技术、恢复通道、会话过期/被清理后的重新绑定与撤销。
- Web主屏安装引导、通知方案及后续App封装。

这些不会由原型的交互默认值自动变成生产决策。
