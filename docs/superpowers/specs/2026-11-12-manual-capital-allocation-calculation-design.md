# MA-CAPITAL-01：人工接管版资金分配与发送检查计算方案

状态：**Owner已批准本地修复，代码候选已完成，正在进行精确提交认证；部署前等待Owner确认，尚未安装或激活。**

## 1. 推荐决定

**固定使用5倍杠杆；先按止损风险计算数量，再用单票资金分配与账户实际承受能力约束数量。单票30%改为“行动时USDT钱包余额的初始分配额度”，全账户90%继续按实时保证金权益检查。**

单票分配在最终出票快照形成并冻结，发送前核对其完整性及当前钱包余额是否仍支持这项分配；已有仓位的浮动盈亏不再反复修改这笔的单票分配上限。实际资金与组合风险则必须继续用发送前的新事实核验。

这是一项**明确的额度语义调整**，不能说成仅修一个比较符或完全不变的风控：

- 原规则：单票额度=实时保证金权益E×30%。
- 推荐规则：单票初始分配额度=行动时钱包余额W×30%。
- 浮亏时新分配额度可能高于旧规则；浮盈时可能低于旧规则。
- 5倍、最多3票、首尔自身的止损风险参数、总保证金90%、人工接管权限及其他门禁不因此扩大或取消。
- 30%约束的是冻结的初始参考保证金分配，不能再把它当作“随市价变化、任何时刻都不许越过的单仓实际保证金比例”。发送时价格引起的实际资金需求变化由账户资金/总额度、报价风险和压力检查承担。此解释也属于Owner需要批准的语义。

**撤回“统一预留1%就能完成修复”的推荐。** 任意余量只能降低发生概率，不能解决分配额度和实时资金门禁混用的问题。本方案没有新增1%经验参数；已知费用、价差通过明确成本公式计算。

## 4. 最终出票计算

### 4.1 先验证是否允许参与

先过账户/品种/方向/策略/配置/管理采集/归属/持仓及残单/事实时效门禁。全局ENTRY lane一次只允许一个新ENTRY；原信号与Episode不能复用；最多3票并不覆盖家族、同方向风险或人工管理阻塞。

读取交易所事实在数据库事务外；进入短事务后锁定现有容量/方向/Policy权威，核对事实有效期及当前占用，不能拿跨版本、跨账号或已过期快照计算。若计算前置条件过期，先结束本次未出票计算并在现有有效信号准入流程内刷新，不写Ticket/Command后再偷偷缩量。

### 4.2 止损风险预算

```text
R_target = max(0, min(W*r, W*rg - Rg_used, W*rd - Rd_used))
R_min = W*r*minimum_materialization_ratio
q_risk = R_target / abs(P0-S)
```

- 当前首尔最低兑现比例为50%，所以W=1500时单票目标30U，最低15U。
- R_target=0或小于R_min时直接以准确原因拒绝。
- 人工仓风险已知则沿既有保守规则计入；未知则阻止新开仓。不能因MANUAL而不占风险，也不能仅凭止损移到保本就释放原方向风险。

### 4.3 单票分配与实时账户额度

```text
M_single = W * 0.30
U = max(I, Rm)
M_gross_remaining = max(0, E*0.90 - U)
A_effective = max(0, min(A, E-U))
```

U只能在其他内部预留与交易所曝光已核实、不存在另一条未完成发送时采用max，不能把已经包含在I里的同一持仓再次相加。若确有未在交易所体现的另一笔准备/未知ENTRY，沿全局lane及未知结果门禁阻止本次准入，不能用max掩盖两项不同义务。发送检查必须精确排除当前候选自己的预留，再加候选一次。

不含费用/价差时的核心数量式：

```text
q = floor_to_step(min(
    R_target / abs(P0-S),
    M_single * L / P0,
    A_effective * L / P0,
    M_gross_remaining * L / P0
), s)
```

### 4.4 已知执行成本的完整公式

核心式用于解释，真正实现必须考虑可证明的费用和当前执行价/标记价差，不用任意百分比替代。

- Pm=max(P0,bid,ask,mark)，均为新鲜、同账号/标的的一组有界事实。保守估算所需初始保证金m_need=q×Pm/L。
- f为认证的保守taker费率上界。缺失不能填0。本次方案按USDT支付假设预留费用，即使Owner开启BNB；BNB实际手续费仍按原币核算，不能虚构扣款。若后续要减少该保守费用预留，须另有可复核的BNB支付保障语义。
- 费用上界F=q×Pm×f。
- 当前执行价相对标记价的初始不利浮动：做多每单位d_open=max(ask−mark,0)，做空max(mark−bid,0)；D=q×d_open。
- D用于准入压力下的即时资金估算，不是承诺市场单的未来滑点上限。

因此在同一最终快照下，数量上限使用：

```text
q_alloc = (W*0.30)*L/P0
q_available = A_effective / (Pm/L + Pm*f + d_open)
q_gross = M_gross_remaining / (Pm/L + 0.90*(Pm*f + d_open))
q = floor_to_step(min(q_risk, q_alloc, q_available, q_gross), s)
```

该q必须满足：

```text
m_ref <= W*0.30
m_need + F + D <= A_effective
U + m_need <= 0.90*(E-F-D)
q*abs(P0-S) <= R_target
q*abs(P0-S) >= R_min
```

所有金额Decimal，无float epsilon。最终q再验证minQty/minNotional、价格保护、精确TP/Runner数量、初始止损、账户维持保证金压力与既有分族/方向/数量限制。失败不抬杠杆、不补仓、不增大q凑TP最低量，除非现有退出计划规则明确允许在既定总q内提升TP份额。

费用/价差输入属于新增完整计算证据，当前四条现场摘要没有保存全部该输入；不得宣称已通过这部分生产式完整回放。

### 4.5 一次冻结

在单个PG事务内，连同原有Claim、Ticket、Reservation、唯一ENTRY Command冻结：

- calculation_contract_version及Policy版本/摘要；
- W/E/A/I/Rm、报价、标记价、费率与规则来源/有效期；
- 单票分配基准wallet_balance、M_single、m_ref；
- m_need/F/D、R_target/R_min、q各约束上限及最终binding_constraint；
- 现有Stop/TP/Runner和风险/压力证据。

账户快照的真实E必须保留。**禁止把total_margin_balance字段偷偷塞成W**来绕过旧验证器；这是两项不同事实，模型和约束应明确区分。

## 5. 出票到发送：冻结分配，实时检查可承担性

### 5.1 冻结什么

Signal/Episode、Policy/规则版本、q、P0、S、初始分配m_ref、W0和分配上限、Claim证据保持不可变。发生时延不重新分配更大仓位；不改变已出票数量。

### 5.2 发送前必须读取并核对什么

1. 新鲜的W1/E1/A1/I1、bid/ask/mark、账户身份/模式/配置杠杆、仓位和挂单；当前Policy、账户/管理健康、lane、方向控制及内部其他预留/风险。
2. 原Policy或规则版本漂移直接拒绝；冻结分配必须不超过原授权上限，也必须满足 `m_ref <= 0.30*min(W0,W1)`。W1变大不扩单，W1因转出/已实现亏损/USDT费用或资金费变小须严格复核。
3. 不能再执行 `m_ref <= 0.30*E1`。删除的正是这项随其他仓位浮动盈亏变化的单票重分配条件。
4. 单票、总、同向止损风险继续按当前钱包余额及Policy复核，精确排除本候选后计一次；更新人工风险信息，不用过时claim累计量代替当前风险事实。
5. 重新算 `m_need1=max(m_ref,q*max(P0,bid1,ask1,mark1)/L)` 和F1/D1，核对账户当前可用资金及总90%权益上限。价格变化可能使实际资金需求高于初始分配m_ref，这是实时资金检查的对象，不能再伪装为固定单票分配被修改。
6. 保留现有报价方向/初始止损有效性、允许的成交后风险上限、交易所档位、维持保证金压力及签名有效窗口检查。

仍可能合法拒绝：真实可用资金不足、全账户90%边界收紧、钱包余额减少、报价变化超限、事实过期、Policy或Owner控制改变、未知归属等。这些拒绝必须清楚区分，不能继续一个margin_drift包揽所有含义。

### 5.3 不能承诺的事

W基准去除了“其他仓位浮动盈亏直接挪动单票30%上限”的耦合，但不会消除全部发送前拒绝。尤其资金费、转账、已实现损益可以改变W，实际费用、价差与行情变化可以收紧账户硬约束。市场单不能事先保证精确VWAP；成交后仍由既有实际风险/压力判定、初始保护、必要时受控收尾流程处理。MANUAL永久不受本方案恢复为AUTO。

## 7. 已比较的其他路径

| 路径 | 优点 | 缺点 | 本方案选择 |
| --- | --- | --- | --- |
| 保持动态E30%，预留固定1% | 改动小 | 只是概率性缓解，浮盈浮亏仍改写单票额度；1%缺实证依据 | 不推荐作为根治 |

## 8. 实施边界

1. 单一纯域计算：新增/提取明确的MarginAllocation与MarginAffordability边界，使用冻结命名Pydantic模型和Decimal；不做两套生产公式，不增加并行交易链。
2. `capacity_sizing.py`、`build_capacity_claim.py`、`capacity.py`、`issue_ticket.py`、`revalidate_entry_dispatch.py`及dispatch诊断必须一致改变；不能只改最终if，导致Claim/出票仍按另一基准。
3. Owner Policy明确持久化分配基准与计算合同版本；Claim/Ticket持久化冻结的版本、W0、单票额度和费用/报价证据，参数更改由真实Owner路径审计。
4. 同一个账户计算/发送事务锁域内读取最新内部其他风险、保证金预留、计数与族槽位；候选自身排除必须有精确ticket_id，无字符串猜测。
5. 新增错误码区分：allocation_wallet_changed、available_margin_insufficient、gross_margin_limit、quote_cost_changed、minimum_materialization_unmet、management_risk_unverified等，并保留数值、时点和因果引用。
6. 控制台用“单票资金分配”“预计5倍保证金”“账户可用保证金”“总保证金限额”“计划止损风险”展示，不能再把这些项目统称预算不足。展示浮盈导致的总额度变化及实际限制来源。
7. 保持唯一ENTRY generation、不可变Ticket和拒绝终态；禁止缩改旧票/自动重发/未知结果重试。现有保护、退出与MANUAL权限不变。

## 9. 数据升级与发布

这是方案阶段，不触发任何生产操作。

- 本方案需要新的明确合同版本及冻结字段，预计前向迁移；具体迁移编号实施时取当时唯一Alembic head，不预占0022。

- 新生产运行只接受新版本准入；历史终态读取保留可解释性。无活动仓位/未知结果的停止writer前向升级，执行现有preservation门禁。
- 不交接活跃旧票，不把历史拒绝票重新启动；停止新开仓、自然flat/终态/无残单、正式认证及真实Owner激活按现有发布合同执行。
- 出问题以停止新ENTRY和前向修复为主，不倒退Schema或恢复旧写入链；既有AUTO保护优先，MANUAL禁写不变。
- 东京是独立产品：本次只比较，不授权东京部署或Policy调整。共同修复可独立移植、独立认证。

## 11. 需要Owner复核的决定

**批准“单票30%按行动时钱包余额形成初始分配，发送时继续校验钱包减资；实时权益负责全账户90%和实际承受能力”的新口径。** 这是本方案唯一需要业务取舍的核心决定；具体字段、代码组织和测试实现是工程工作。

5倍已由Owner明确支持，不再次请求确认；当前首尔自身风险比例、最多3票、族及方向门禁不随本提案提高。固定1%余量不作为本方案参数。本轮Owner已授权按推荐口径本地编码测试；Policy生产激活和部署仍须按正式发布门禁与Owner确认执行。

## 12. 方案比较补充：提高杠杆是否更好

**本设计不是被证明唯一或全局最优的方案。** 选择取决于“保留固定5倍并稳定执行”还是“在既定风险上限内提高资金效率”。当前Owner支持5倍，尚未授权改变实际交易所杠杆。

### 12.1 必须区分两种杠杆变更

1. **数量保持不变，只提高L**：名义金额N及到同一止损价的计划损失不变，初始保证金N/L降低。账户实际交易模式为Cross，不能用简单“爆仓距离=1/L”解释风险；应核验真实账户权益、维持保证金档位及原压力模型。更低的初始保证金并不代表手续费、滑点或缺口风险凭空减少。
2. **提高L后重新按风险预算计算q**：此前被保证金上限截小的仓位可以增大，计划止损风险也从较低值升向Owner允许上限。虽然不突破获准上限，但相对于原较小订单，实际名义敞口和计划亏损增加，必须明确披露。

XRP原q2156.7、名义2261.51562、5倍保证金452.303124。仅改6倍且数量不变时保证金376.91927。若重新计算至完整风险目标，q可达2476.0、名义2596.33360、6倍保证金432.7222667，计划止损风险由26.31174变成30.20720U。两个操作并非同一方案。

### 12.3 其他方案取舍

| 方案 | 主要收益 | 限制与代价 | 适用判断 |
| --- | --- | --- | --- |
| 固定5倍＋W分配/E实时承受能力 | 消除其他仓位浮盈亏直接改写单票分配；不新增杠杆控制链 | 分配基准变化需Owner批准，行情/费用/总额硬限制仍可能拒绝 | 当前固定5倍目标下优先方案 |
| 固定5倍＋保留E30%＋执行余量 | 保留现有资金规则，实施较小 | 只能降低拒绝概率；余量需数据验证，可能降低风险兑现 | 不接受基准调整时的有效保守替代 |
| 按需选择5—10倍 | 更容易用完获准止损预算，减少单笔初始保证金占用 | 更复杂的持久杠杆命令、账户读回、认证；更大q可能提高实际风险；最高10倍时仍会贴边 | 资金效率目标下值得独立设计 |
| 统一提高到10倍 | 设置概念较少、部分候选有更大资金空间 | 不适合所有止损距离，不能修掉实时边界耦合；同向风险/票数等限制不变 | 不作为本次直接修复 |
| 最终出票前再采样/缩短事实到发送间隔 | 降低事实漂移，提高输入一致性 | 外部事实与DB/交易所之间不能原子提交，无法根除边界拒绝 | 所有方案的辅助工程改进 |
| 放宽或删除单票30% | 更多账户资金可用于单笔 | 改变集中度和并发分配，不是免费技术修复 | 仅明确产品决策时考虑 |

### 12.4 为什么10倍也不能保证足够

若只看单票风险目标r、单票资金比例alpha、相对止损距离delta：

```text
目标名义金额≈W*r/delta
保证金≈W*r/(delta*L)
要求L>=r/(alpha*delta)
```

例如r=2%、alpha=30%、止损距离0.2%时，理论需要约33.33倍（整数至少34倍）才能在30%保证金内完整兑现风险。10倍仍需缩量，仍可能贴着资金边界。该例只解释数量关系，不建议使用34倍；退出可执行性、风险最低兑现和总账户门禁仍可能直接拒绝。

### 12.5 推荐顺序及授权边界

当前修复目标下，继续优先审议本文“明确分配语义＋实时账户承受能力”的方案，并补齐费用/报价与最新事实输入。若Owner不接受W基准，保留现有E基准配合有实证依据的余量也是合理方案，但须接受仍有合法边界拒单。

若Owner改为以提高风险预算兑现率为目标，则另行设计**按需最小适当杠杆、上限10倍**，并且必须与明确的额度/事实复验规则结合；不能仅把常量5改10。当前代码会拒绝实际配置不等于5的账户事实，并拒绝SET_LEVERAGE分支；Policy中max_leverage=10不是已实现或已授权自动调杠杆。杠杆变更需独立持久Command、flat且无挂单/未知结果、归属与真实回读校验，持有MANUAL或已有仓位时不得擅改。Tokyo独立部署不在本次范围。

本补充仅为方案与离线算术比较；未改变账户杠杆、Owner Policy、运行代码或生产部署。
