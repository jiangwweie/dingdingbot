# Owner确认：主动减仓替代原TP1数量退出

> **执行分支统一入口：** [人工操作后自动续管V1](2026-11-16-owner-cooperative-execution-v1.md)已纳入Owner避免并行退出的决定及撤TP/减仓失败恢复。本篇冲突减仓流程仅保留溯源，以该入口为准；未开始编码。

日期：2026-11-16。状态：**业务规则已确认，执行细节待完成设计；未授权本轮编码、部署或生产操作。**

## 1. 确认语义

Owner通过本系统主动减仓，可以发生在浮盈或浮亏阶段；它同时降低未来金额风险与未来获利规模，不称为已盈利或原TP1成交。

**实际人工减仓替代原TP1的减仓动作。原TP1尚未完成时，取消其待成交数量退出；保留原目标价作为后续保本/Runner的管理转换条件，不在该价再减一次仓。**

- 余仓保留已有保护与原策略失败/时间退出。
- 原目标价尚未达到时，不因为减仓就提前保本或启动Runner。
- 原目标价后续条件满足时，按明确价格事实申请余仓保本，保护确认后继续原Runner。
- 已经进入Runner的票减仓后继续Runner，不倒退或重置阶段，不放松已确认保护。
- 价格条件与成交是两类证据；不能伪造TakeProfitFilled或已实现盈利。

本决定仅针对系统内受控减仓；币安App外部介入仍按现有管理权规则处理。既有已成交TP、人工成交、费用与资金费保留真实账务，不改写历史。

## 2. 盈亏含义

浮亏减仓会兑现部分亏损；余仓后来达到费用感知保本，并不代表整票保本。显示已实现盈亏与余仓结果，不为追回已实现亏损自动提高风险、改变目标或加仓。

浮盈减仓同样可能减少后续趋势利润。这是Owner主动减少暴露的双向取舍，不是需要系统纠正的偏差。

## 3. 取代的旧建议

| 旧建议 | 当前状态 |
|---|---|
| 减仓后等比缩减原TP1待成交量 | 不采用；小TP可能缩至不可执行 |
| 保持原TP1待成交绝对量 | 不作为默认；大TP可能吃掉全部余仓 |
| 人工减仓直接算原TP1完成并立即保本 | 不采用；实际减仓可发生在浮亏、原盈利条件未满足 |
| 减仓会与原TP1数量冲突时必须先手工改TP | 对本决定涉及的原自动TP1不再适用；由受控操作执行取消与转换 |

独立人工止盈计划的替换/取消仍遵循此前Owner决定；不能把“取消原自动TP1”擅自扩大为“取消任何人工计划”。两者同时存在时的优先关系需在详细状态设计中明确。

## 4. 必须继续完成的技术设计

1. 原TP取消与减仓实际成交的顺序、期间成交/部分减仓、失败或未知结果的核实及恢复；不裸撤保护。
2. 原目标价条件使用的参考价格、数据新鲜度、首次触及证据、重启恢复、减仓之前或执行中已触价的处理；禁止事后仅凭历史高低点补造条件满足。
3. 至少有实际减仓成交才能形成有事实依据的计划转换；未成交失败、极小部分成交的后续状态须明确，不以接受请求代替结果。
4. 目标条件已满足但价格回穿保本位置时，沿明确生命周期分支退出/处理，不能挂非法保护或自行放松。
5. 原自动TP1部分成交、原TP已满额、已有人工TP、重复人工减仓等状态逐项覆盖；一次转换幂等。

上述由工程方设计，必要的实质业务分歧再沟通。当前不冻结未经确认的价格触发算法或失败补偿行为。

## 5. 当前范围

仍只推进执行可靠性和人工协作，不修改正常无人干预票的入场、MA50、风险、TP、保本或Runner规则。这里新增的是**Owner主动减仓后该票的明确管理分支**，不是方案A或全策略无TP改造。
