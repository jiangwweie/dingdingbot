## 2. 决策状态与Owner输入

### 2.1 已确认且不重复询问

- 系统独立运行、结构退出为主，Owner偶尔收紧/减仓/暂停；不默认固定回吐阈值。
- 同币同向局部失败暂停，结构重建后自动恢复；策略区别顺逆势。
- 首版不加仓、不提高账户/单票上限，非高频，单票串行。
- 手机主屏Web，必要写操作，单可信注册、长期登录、不使用TOTP。
- 市价减仓/全平、单个人工TP、Stop只能收紧不可裸撤、部分减量续管、全局与策略开关不影响旧仓保护。
- 原型通过；产品意图通过交互、功能和信息流表达。

### 2.2 Owner已确认的补充决定（2026-11-16）

| 编号 | 已确认规则 | 当前状态 | 实施边界 |
|---|---|---|---|
| Q1 | 人工TP用普通GTC限价；减仓与原TP数量冲突仍先改/取消，不自动联动；同结构两次失败暂停，无新增全账户日熔断 | Owner明确同意按这组边界设计 | 规则确认；未授权开始编码或激活 |
| Q2 | 仍有自动TP的票，人工TP替换原获利退出计划；人工计划目标满额真实成交后触发原BE/Runner；取消后不擅自恢复旧TP | Owner明确同意人工计划替换、成交后续管 | 规则确认；无固定TP票的人工部分兑现语义独立，未授权开始编码或激活 |

Q2已选择人工计划替换分支。取消人工计划不恢复旧TP；不因异常临时切换到其他业务语义。实现能力未通过验收前仍禁用相应入口。

### 2.3 工程定义V1，Owner授权工程方负责具体定义

- Owner已确认无有效突破不做、初期50%目标风险、确认后新机会正常风险、已有试错仓不加仓。
- 工程定义V1：BTC4h SMA50/ATR带与两次确认；币种1h首次突破冻结边界，后两根内守住＋ER确认；正常/半风险/拒绝矩阵。
- 20根冻结局部区间、新突破或新6根收敛结构恢复。
- SOR1.2R闭合＋1h结构保护确认进入趋势；BRF2等退出保留。
- 180天闲置会话窗口、每7天有效使用续期、30秒预览、60秒nonce、10分钟绑定资格。

这些是工程方选定的明确初始规格，已补定义层面核验，供整体行为复核，不逐项要求Owner猜参数。不是“已实证最优参数”；允许后续在不突破已批准业务边界的前提下有版本地修订，并重新回放。

## 3. 推荐分段：界面、执行、策略可独立验收

| 工作包 | 内容 | 依赖与完成标志 |
|---|---|---|
| W0 协议与源码契约验证 | Hedge只减仓竞态、Stop替换、普通TP/取消/部分成交、真实字段归属 | 读取正式协议与精确CCXT版本，原始协议回放；不能靠正向Fake给安全结论 |
| W1 授权持久化 | 单注册、绑定/撤销、长期会话、nonce/签名/CSRF、新Owner授权用途 | 重启仍有效、撤销立刻阻止新发送；历史TOTP保全且不伪造 |
| W2 票级操作 | reduce/close/tighten/TPset/cancel，部分效果和未知结果恢复 | 一条Command链，真实数量守恒，保护持续，Q2语义已确认 |
| W3 手机客户端 | 已确认原型接真实API，状态、主屏、可选通知 | 不缓存交易API、不离线重发、无需TOTP、当前操作能审阅与追踪 |
| W4 无TP生命周期 | 显式退出计划、趋势里程碑、SOR阶段、保护/时间解耦 | 无假TP、旧历史保全，旧模式有真实成交语义 |
| W5 准入与局部试错 | snapshot、风险乘数、结构身份、失败结算/暂停/恢复 | 不把新标签替代原Signal，不越过Owner暂停/风险上限 |
| W6 全链与回放 | 成交协议、生产形状并发、顺序组合与多行情验证 | 规则正确、代价可见；不是收益保证 |
| W7 独立发布准备 | 精确候选、前向迁移、保全、现场门禁、安装与Owner恢复 | 另获部署授权，当前事实逐项通过 |

W4/W5可以在本地与W1/W2并行设计，但不依赖创建子代理或额外工作区。没有授权前不开展生产实现。

手机上线与策略激活分开决定：先具备有证据的操作能力，再选择新配置。**不能上线一个看似可点、后台保护/授权协议尚未完成的操作按钮。** 新Schema安装也不自动打开新入口或新策略。

## 4. 关键行为验收矩阵

### 4.1 认证与操作

| 编号 | 场景 | 必须结果 |
|---|---|---|
| A01 | 同一绑定资格重复/并发消费，过期或错误码 | 最多一个活动注册；过期拒绝；不暴露令牌 |
| A02 | API/worker重启、会话有效使用续期 | 登录持续；没有再次要求TOTP；授权事件来源准确 |
| A03 | 换机撤销、旧nonce/旧cookie/旧key | 旧注册不能发新操作；已发送订单继续核实而非丢弃 |
| A04 | CSRF、Origin错、签名/body篡改、nonce重放 | 全部拒绝，不形成Command |
| A05 | 允许移动Resume但尝试风险/Selection配置扩权 | 只有已列用途允许，其他用途明确拒绝 |
| A06 | 预览后Stop/TP/仓位/管理权变化 | 返回过时，不按旧意图下单 |
| A07 | 同幂等key重试/不同body | 返回同一operation或冲突；无重复命令 |
| A08 | 减仓部分成交、Stop同时触发、quantity归零 | 无新反向暴露/加仓，实际余量与保护一致；结果不明不重发 |
| A09 | Stop替换失败/未知，旧保护已有触发 | 保持/核实原保护，显示真实部分效果，不先撤唯一Stop |
| A10 | 人工TP替换期间旧TP成交、取消失败 | 累计成交和新量准确，无双份超量TP |
| A11 | 全平后残单未确认 | 继续收尾，域和风险占用不提前释放 |
| A12 | 外部App介入/REVIEW、Owner请求在途 | 管理权优先；不能把原系统请求误判外部或把MANUAL带回AUTO |
| A13 | 新开仓全局/策略pause/resume | 旧AUTO保护继续；全局恢复不打开Owner单独停用策略 |
| A14 | 离线、关闭PWA、刷新、推送失败 | 不离线发单/重发；后台继续；前台回来按真实operation状态恢复 |
| A15 | 确认阶段输入非法、Stop放松、数量最小边界 | 后端独立拒绝，不能仅前端校验 |

### 4.2 交易与风险

| 编号 | 场景 | 必须结果 |
|---|---|---|
| T01 | 尚未闭合/缺K线/旧snapshot/历史后修订 | 不使用未来或过时数据；旧判断可重建，不被新snapshot倒写 |
| T02 | 大盘阈值边缘来回波动 | 按明确确认次数转换，不每tick重算/翻转 |
| T03 | BRF2逆大盘但原strong_uptrend_disable | 原禁用优先，半风险不能绕过 |
| T04 | 半风险、最低materialization和最小交易量 | 按有效目标计算；不足拒绝，不补大仓位 |
| T05 | Claim后环境转差/转好 | 转差终止未发ENTRY；转好也不扩大冻结量 |
| T06 | 信号false/true、跨策略同币同向尝试 | 原rearm不自动清局部结构失败账；不会复用旧Episode |
| T07 | 同Ticket重复结算/Review修订/进程重启 | 失败最多一次计数、暂停可恢复且不丢状态 |
| T08 | 暂停后只时间流逝、无新结构 | 不自动解锁；真正新结构才恢复，Owner暂停仍有效 |
| T09 | 已有仓位遇市场/局部准入标签变化 | 不批量强平或撤保护；按本票计划运行 |
| T10 | SOR无TP且达里程碑但保护未确认 | 不假报TREND_ACTIVE、不伪造真实成交 |
| T11 | 原失败条件与趋势确认同时成立 | 失败退出优先，不能用阶段转换绕过失效 |
| T12 | 15m守卫/1hRunner/UTC日界与24h期限 | 分别按冻结语义，周期调整不意外延长原试错期 |
| T13 | Owner更紧底线与Runner冲突 | 只收紧，部分兑现/重启不放松底线 |
| T14 | 停止/恢复新配置，旧票活动 | 旧票冻结计划不改；不做活动仓schema移交 |
| T15 | 相同输入与版本、本地/生产域函数 | 产生一致状态、数量和理由码；无并行策略实现漂移 |

先红绿编写核心行为测试，复用当前纯域与手动产品PG。原始HTTP/WS经过实际CCXT和归属解析；策略回放与执行故障测试分开。正式认证仍走项目完整Release tier，而非只跑这些示例。

## 5. 回放和经济证据

至少分为：原完整已批准基线、仅新SOR退出、仅新准入/风险/局部试错、组合新规则。行情划分按事前规则而非事后挑赢家；覆盖上涨、下跌、区间震荡、快速反转。时间顺序产生全部合格Signal，包括原未成交机会；按变化后钱包、资金流、保证金和方向风险重算Claim，不只固定18票求和。

输出真实/模型分开：净R、费用/资金费/滑点、胜负分布、最大/连续亏损、持仓权益回撤、利润回吐、趋势收益集中度、试错耗损、暂停误伤/恢复延迟、容量排挤、长期占仓。相同输入规则分层可重建。

不要求先承诺稳定盈利；但不能仅因某个净收益数字更大就跳过已发现的资金或保护问题。经济结果可能支持撤回某个候选参数或缩小策略范围，仍由Owner决定业务取舍。

## 6. 发布、迁移与失败恢复

- Schema演进在现有单条forward链；先确认真实Owner暂停、flat、无挂单、内部终态、无未知Command，停writer后迁移。
- 保全历史Ticket/成交/Review、Owner控制及真实授权证据，不回写模拟结果、不删除旧失败。
- 新设备/会话表初始无授权设备；不能凭部署自动生成Owner身份或Resume。独立渠道绑定是安装后的真实Owner动作。
- 新runtime capability默认未激活；精确代码/Schema/账户身份、官方认证及promoter完成才可请求Owner通过新批准授权方式恢复。
- 新授权用真实trusted_device_session，不伪造TOTP；旧Web相关控制要统一收敛到同一授权服务和scope，不留下可越权的旧接口。
- 失败先停止新增动作/新准入，保留已有保护及已确认Owner约束，前向修复；不能降级至不认识新阶段/新约束的旧writer。
- 设备撤销不停止正常AUTO保护；授权恢复、策略激活、手机更新是三个独立状态。

## 7. 设计交付完成与剩余边界

本设计包已给出具体规则、状态、数据对象、API、事务/网络边界、失败策略、分段工作及验收矩阵。**当前不开始编码。**

Q1/Q2业务分歧已关闭；其他具体算法数值仍为详细设计候选，不因这两项确认自动视为全部参数批准。保留一项实现前证据门：Binance USD-M Hedge下Stop与减仓竞态/保护替换的真实协议行为。若不能证明安全，必须改变实现方式或限制操作，不能将此不确定性藏在“低频”的假设里。

后续真实开发需以最新源码和现场身份复核；本稿没有复制生产SHA/Schema或声称当前服务器已满足发布条件。
