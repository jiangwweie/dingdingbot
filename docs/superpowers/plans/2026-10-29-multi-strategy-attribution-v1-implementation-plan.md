### A1：先固定口径，再计算

1. **固定两个既有窗口。** 沿用调研快照的近期和较长窗口，不因某策略结果不好而移动起止时间。主统计按 `terminal_at_ms` 落在半开区间 `[from_ms, to_ms)`；跨期持仓及窗口末未结束持仓单列。
2. **固定 Review 版本。** 使用快照中 aggregate 指向的有效 Review，不以本地当前时间重新挑历史最高修订，也不将多次修订重复统计。
3. **固定总体分层。** 终结 Ticket、实际暴露证据、ENTRY 拒绝、未结束持仓分别列示；终结不自动等于成交完整。旧策略和旧版本不冒充现行版本。
4. **固定维度。** 策略/版本、方向、标的、冻结 ExitProfile、Policy、出生 Selection 身份和退出类别来自当时持久化事实。缺失 authority 标为 unknown，不自动归为 Static。
5. **固定成本定义。** 净收益沿用 canonical Review；资金费为带符号金额，缺失不补零。实际成交价格已体现执行滑点，不能再次扣减。
6. **固定可复现入口。** 输入清单记录来源快照时间、代码身份、文件 SHA-256、分析代码摘要、窗口和规则版本。已有可变采集脚本不直接对冻结目录重跑；确需刷新时写入新的时间戳目录。

### A2：先描述实际贡献，不评判长期优劣

- **贡献矩阵：** 五策略及版本/方向分层的 Ticket 数、各指标覆盖数、已知毛收益、费用、资金费、净收益、计划风险 R、盈亏分布。
- **同样本成本表：** 只对经济完整的同一组 Ticket 验证毛收益减费用加资金费等于净收益。全体已知毛收益与部分已知净收益分别展示，不能跨总体做桥接。
- **退出分区：** 使用 canonical `strategy / owner / safety / unknown`，各分区不重不漏地加回总体；Owner 退出不混入策略自主退出解释。
- **集中度：** 大赢家与大输家贡献、最大盈利单剔除敏感性。没有盈利单时最大赢家为空；右尾依赖本身不作为否定策略的理由。总体净值接近零或为负时，不用不稳定的净收益占比误导读者。
- **R 单位：** 采用冻结计划止损风险作为计划 R 分母，实际风险 R 如展示必须另列；累计 Ticket R 不是组合资金收益率。

### A3：逐单解释与有限补证

**样本规则在查看解释结果前固定：** 每策略全部已知亏损、最大三笔已知盈利、全部 Owner/安全/unknown 退出及全部经济缺失样本；去重后分析。数据量小的策略自然覆盖全部交易。

1. 每笔解释连接 Signal、Ticket、冻结策略/退出身份、ENTRY 成交、TP1、保护/退出事件与有效 Review。
2. TP1 与后续退出先报告**可直接归属的成交毛收益和成交手续费**；ENTRY 手续费及无法精确分段的资金费保留 Ticket 公共成本桶，使分段加公共桶等于总结果。不能默认均摊后宣称精确 Runner 净收益。
3. 没有 TP1 或后续平仓证据时，不按字段名称猜 Runner；不能用离场后的 MFE 作为“漏赚利润”。
4. 缺口按“已有本地证据可解释 / 需要精确远端证据 / 现有证据不可恢复”归类。确需补证时只针对准确身份做有界只读查询；交易所查询仅走已有只读适配器，不扫全账户历史，不修改 Review。
5. 补证具有独立采样时间，作为附件与原快照结果分开。发现新事实不静默重写冻结基线；需要更新分析时创建新运行版本。
6. 无法恢复的费用或成交继续为 unknown；不能为清空缺口扩展成采集平台或生产修复项目。

### A4：组合分析保持可证明范围

1. **日度贡献：** 按统一时区的终结日归集已实现结果；明确它不是每日盯市收益。已知结果的累计曲线不是账户权益曲线，不报告未经资金流与浮盈亏支持的组合收益率、夏普或真实账户最大回撤。
2. **持仓重叠：** 优先用首次真实 ENTRY 成交至可证明平仓的时间区间，窗口末持仓截断并标明尚未结束。只识别同方向、同标的与时间上的重叠；Ticket 创建时间不能冒充成交时间。
3. **风险占用：** 冻结计划风险可作为入场风险承诺代理，不能冒充持仓全程实时风险。缺乏动态风险/权益历史时不制造精确资金利用效率。
4. **运行时长：** 已有启停事件可重建的只是控制状态区间。缺少区间起点或 Authority/Readiness 证据时保留未知，不据此计算每有效交易小时收益排名。
5. **未承接机会：** 现有 AdmissionDecision 按策略、Policy 和真实 first blocker 分组。当前调研只有部分聚合字段，无法支持逐时预算反事实时直接标明限制；不为“如果换仓”估值重新搭建模拟交易链。
6. **Shadow 覆盖：** 分开报告完成、待完成、不可用、额度跳过及停用缺口；样本不是完整信号总体，其涨幅不进入真实利润。

## 五、验证计划

**采用小规模、针对数据风险的验证，不重跑整套交易发布认证。** 实施时先为真实错误风险建立失败样例，再完成解析或计算；不编写只验证文案或镜像实现的测试。

| 检查 | 必须拒绝或显性化的情况 | 通过证据 |
| --- | --- | --- |
| 输入与身份 | 文件摘要变化、重复 Ticket、错误 Review 指针、未知关联被自动回填 | 明确失败或保留 unknown；无静默纠正 |
| 窗口与总体 | 创建日替代终结日、边界重复、未终结混入已实现收益 | 半开区间与跨期样例通过，总体可核对 |
| 金额与覆盖 | 缺失资金费按零、不同覆盖总体相减、重复扣滑点 | 同样本恒等式及逐指标分母通过 |
| 归因与分段 | Owner 退出归为策略、重复成交、分段成本重复计入 | 分区/分段加回总体；未知原因保留 |
| 风险与集中度 | 变化后的风险分母、亏损单被称最大赢家、负净收益占比误导 | 冻结分母、无赢家场景和稳定展示通过 |
| 运行上下文 | paused 当作无机会、enabled 当作全部可交易、Shadow 当成真实利润 | 边界样例与报告标注通过 |
| 可复现性 | 同输入重跑改变业务结果、未记录分析代码版本 | 规范化 JSON 摘要一致；时间等运行元数据单独记录 |

金额源值保留原精度，展示才舍入。精确加总应与冻结 canonical 结果一致；涉及历史精度除法的公式复算沿用调研中已记录的 **1e-20** 舍入容差，并报告最大差异，不能以容差掩盖分组或金额差错。
另选不同退出类别、缺失类别和大额贡献的真实样本核对原始成交与事件，避免仅用同一汇总函数自证。

## 六、推进机制与异常处理

**阶段通过即继续下一阶段，常规实现、分组、只读核查、验证和报告不逐项等待 Owner 确认。**
负责人在主路线图记录完成项、证据路径和真实阻塞；进度汇报说明发现、验证和剩余工作，不重复询问“是否继续”。

- **数据不足：** 降低对应结论强度，完成其余部分；不把未知全部转化成阻塞。
- **离线计算矛盾：** 暂停受影响指标的发布，先核对身份、窗口与公式；不能输出两个未经解释的收益版本。
- **发现生产问题：** 记录精确证据和影响；实际保护/退出故障按既有 P0 规则处理，但归因计划本身不授予生产改动或策略扩权。
- **范围扩大：** 新采集、schema、服务、资本、策略或交易权限改变属于独立事项；先完成可交付的只读结果，不能以此拖住整份报告。
- **未找到 ALPHA-01：** 标明无法复核，继续使用已冻结且已独立核验的数据，不重复等待交付包。

## 七、最终交付与验收定义

### 必须交付

1. **一份中文归因报告：** 目标、来源、口径、客观事实、分析、结论边界和安全证明分开。
2. **可追溯结果：** 策略贡献、同样本成本、退出贡献、集中度、关键交易、组合上下文、覆盖与缺口。
3. **可复现分析包：** 输入清单、脚本与规则版本、运行命令、验证结果和校验和；无凭据、无生产写路径。
4. **路线图收口：** A0–A5 按实际证据更新，首版归因完成与长期优势证明、完整 live economics、GS-13、自然交易验收分别表述。

### 完成边界

**报告可以以“部分证据不足”结束，但不能以“金额无法核对”结束。**
关键净收益、总体和分区必须可核对；缺失清单必须完整；同一冻结输入可重复生成相同业务结果。
最终回答直接交付结果和局限，不以建议列表、下一轮选币工程或追加审批代替本轮交付。

方案落盘只表示工程已拆解，**不表示 A1–A5 已完成，也不创建后台自动执行任务**。
